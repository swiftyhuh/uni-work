fork / wait / process tree

pid_t pid=fork();
pid == 0  child
pid > 0   parent; value = child PID
pid == -1 error
Both continue after fork; memory copied, not shared.
Every process reaching another fork creates a child.

wait(NULL): reaps ONE terminated direct child;
NULL only means ignore exit status.
No direct children → wait returns -1 (ECHILD).
waitpid(pid,&st,0): chosen direct child.
Parent waiting sleeps; child/grandchild may continue.
zombie = exited child, status not reaped.
orphan = parent ended first; child adopted.
wait does not wait for grandchildren/all children.

exec family

execl(path,arg0,...,NULL)
execlp(prog,arg0,...,NULL)   p searches PATH
execv(path,argv)             v gets vector

execl("/bin/ls","ls","-l",NULL);

Success: same PID, image replaced, never returns.

arg0 normally program name; list ends NULL.

Files / links / descriptors

FD 0 stdin, 1 stdout, 2 stderr.
Hard link = new name → same inode; not a copy;
cannot cross FS. unlink decrements link count.
Data freed at links=0 AND no process has it open.
Symlink = separate file containing path; can cross FS;

Process vs thread

Process: isolated memory/faults; good for exec/separate
programs. Thread: shares globals+heap; cheaper communication
and switching, but races/faults affect same process.

pipe behavior

int p[2]; pipe(p);  p[0]=read, p[1]=write
Create before fork so both inherit descriptors.
Close every unused copy; duplicate writers delay EOF.

read when data exists → returns bytes immediately
empty + any writer open → blocks
empty + all writers closed → returns 0 (EOF)
full + reader exists → write blocks
all readers closed → SIGPIPE / EPIPE
read/write may be partial: loop until done.
One pipe is one-way; two-way IPC needs two pipes.
Pipe as semaphore/token: write byte=post; blocking read=wait.
Empty pipe blocks reader until token arrives.
EOF depends on ALL write descriptors closed.

dup / dup2 / open / pipeline

int save=dup(1);          // save stdout
dup2(fd,1);              // stdout → fd
dup2(save,1); close(save);// restore
After dup2, closing original fd leaves duplicate open.

int fd=open("out",O_WRONLY|O_CREAT|O_TRUNC,0644);
// O_CREAT requires mode; O_TRUNC overwrites.

ls child:   dup2(p[1],1); close ends; exec ls
grep child: dup2(p[0],0); close ends; exec grep
parent: close both ends; wait twice
Writer uses p[1]; reader uses p[0].

FIFO / popen

mkfifo("x",0600);  unlink("x");
FIFO=named pipe; bytes in kernel buffer, not file.
open O_RDONLY blocks until writer opens.
open O_WRONLY blocks until reader opens.
Opposite open order avoids two-FIFO deadlock.
One FIFO one direction; use X and Y for duplex.

FILE *f=popen("cmd","r"); // parent reads child stdout
FILE *f=popen("cmd","w"); // parent writes child stdin
pclose(f); // close + wait child (avoid zombie)
Sketch popen(r): pipe→fork; child dup2(write,1), exec
"sh -c cmd"; parent fdopen(read,"r"); pclose→waitpid.
"r"/"w" are from parent’s direction.

pthread create / join / arguments

void *worker(void *arg){ return NULL; }
pthread_t t[N]; int id[N];
for(int i=0;i<N;i++){
 id[i]=i;
 pthread_create(&t[i],NULL,worker,&id[i]);
}
for(...) pthread_join(t[i],NULL);
Threads share globals+heap; own stack+registers.
Never pass shared loop &i; use stable id[i].
Never return &local. Return malloc result; joining
thread reads and frees it. Join can block caller.

Mutex / RWLock

pthread_mutex_t m=PTHREAD_MUTEX_INITIALIZER; // static
pthread_mutex_init(&m,NULL); // dynamic
lock; unlock; destroy
Critical section = shared-data access. Same shared
invariant must use same lock. Keep region minimal.
Locking already-held normal mutex by same thread blocks
(self-deadlock); other thread blocks until unlock.

rwlock_rdlock: many readers, NO modification
rwlock_wrlock: one writer, excludes all readers/writers
unlock; writer may starve under continuous readers.
Mutex→wrlock preserves exclusion, more overhead.
Mutex→rdlock lets modifiers race. RWLock→binary sem makes
all readers serialize: correctness may remain, concurrency lost.

Condition variable

pthread_cond_t c=PTHREAD_COND_INITIALIZER;
// or cond_init(&c,NULL); ... cond_destroy(&c)
lock(m);
while(!ready) pthread_cond_wait(&c,&m);
use_resource();
unlock(m);

Producer: lock; change predicate; signal; unlock.
cond_wait atomically unlocks+sleeps; before return it
relocks m. while rechecks after wake/spurious wake/race.
State: RUNNING→BLOCKED; signal makes waiter READY.
signal wakes one; broadcast wakes all (many can proceed
or different predicates). Signal without predicate lock
can cause lost wake-up/check-wait race.

Semaphore / barrier / producer-consumer

sem_init(&s,0,K); wait decrements or blocks at 0;
post increments/wakes one. Any thread may post; mutex
has ownership and owner unlocks. K permits ≤K entrants.
Alternation A/B: sem A=1, sem B=0; wait own/post other.
Replacing lock calls with sem_post grows count/opens gate.

Producer: wait(empty); wait(mutex); insert;
          post(mutex); post(full)
Consumer: wait(full);  wait(mutex); remove;
          post(mutex); post(empty)
Wait empty/full BEFORE mutex or deadlock.

barrier_init(&b,NULL,N); barrier_wait; destroy
Exactly N arrivals release together; reusable rounds.
For each kind: total arrivals % N = 0; N=1 passes now.
Leftover thread hangs. To change count: after unused,
destroy then init, or use separate barrier.

Deadlock / Coffman / lock ordering

Deadlock needs ALL: mutual exclusion; hold-and-wait;
no preemption; circular wait. Break one to prevent.
Practical fix: global lock order (low address → high).
T0 locks A then B; T1 locks B then A → possible cycle.
Starvation: one waits indefinitely while others progress.
Deadlock: involved threads cannot progress.
Lock A, lock B, unlock B, unlock A is good IF every
thread acquires A before B (unlock order not cause).

SIDE 2 — OS Theory · Scheduling · Memory · RAID · Inodes

ABBREV: OS operating system · CPU central processing unit · RAM random-access memory · I/O input/output · IPC inter-process communication · PID process ID · PCB process control block · LDE limited direct execution · PC program counter · SP stack pointer · FD file descriptor · FS filesystem · FCFS/FIFO first-come-first-served/first-in-first-out · RR round robin · MLFQ multi-level feedback queue · SJF shortest job first · STCF/SRTF shortest time-to-completion/remaining-time first · VM virtual memory · MMU memory-management unit · VA/PA virtual/physical address · VPN/PFN virtual-page/physical-frame number · PTE page-table entry · PTBR page-table base register · AMAT average memory access time · OPT optimal · LRU/LFU least recently/frequently used · R/W/X read/write/execute · RAID redundant array of inexpensive disks · IOPS I/O operations per second · EOF end of file

Process / LDE / PCB / syscall

Process = OS abstraction of running program.
CPU virtualization = time-sharing one CPU.
LDE: run user code directly for speed; retain control
with user mode, traps/syscalls, timer interrupts.
User mode restricted; kernel mode privileged.
System call: library wrapper → trap → kernel handler →
return-from-trap. A library call is not automatically a
syscall. Trap does not imply context switch.
PCB: PID/state, PC/SP/general regs/flags, scheduling,
memory mappings, open files. Register context is saved
on stop and restored on resume.
Context switch: save A → choose B → restore B.
OS is passive while user code runs; timer regains CPU.
VM goals: transparency/private illusion, efficiency in time
and space, protection/isolation between processes+OS.

Process states

RUNNING = on CPU; READY = runnable, waits CPU;
BLOCKED/WAIT = waits event/I/O.
READY → RUNNING scheduled
RUNNING → READY preempted / timer
RUNNING → BLOCKED blocking read/wait/I/O/sleep
BLOCKED → READY event/I/O complete
Completion is not BLOCKED→RUNNING.
CPU-bound = mostly CPU, long bursts, little I/O.
I/O-bound/interactive = frequent blocking, short bursts.

Scheduling formulas / policies

turnaround = completion − arrival
response = first_run − arrival
waiting = turnaround − required_runtime

FIFO/FCFS nonpreemptive arrival order; convoy effect.
SJF nonpreemptive shortest ready job; optimal average
turnaround only with known runtimes/ideal assumptions.
STCF/SRTF preemptive SJF; least remaining work.
RR each ready job gets quantum. Small q: response good,
more switch cost. Large q approaches FIFO.
Scheduling with I/O overlap improves utilization.
Turnaround favors completion; response favors interactivity.

Deadlock answer template

Deadlock = permanent circular resource waiting.
Coffman: mutual exclusion + hold/wait + no preemption +
circular wait. Prevent by breaking ≥1; common student
answer: impose fixed global resource/lock acquisition order.

MLFQ — exact rules

1 Higher priority runs first.
2 Same priority uses RR.
3 New jobs enter top priority.
4 Quantum = max one CPU turn.
5 Allotment = cumulative CPU time/job/level.
6 Exhaust allotment while work remains → demote.
7 I/O/yield does NOT reset used allotment.
8 Periodic boost: all active jobs → top; prevents
  starvation and adapts changed behavior.
Gaming: run 99%, issue I/O, repeat. Fix: cumulative
accounting across all pieces. MLFQ approximates SJF from
observed behavior; favors interactive jobs.

Lottery / stride proportional share

CPU share ≈ job tickets / total tickets (long run).
Lottery: random winner [0,total−1], cumulative scan;
first cumulative total > winner runs. Short-term random.
Currency: user divides own fixed share locally.
Transfer: donor−x, named receiver+x; total unchanged.
Inflation: create tickets; changes relative shares; trust.
Ticket assignment is policy, not solved by mechanism.

stride = BIG / tickets
run job with minimum pass; then pass += stride.
More tickets → smaller stride → runs more often.
New job starts near current minimum pass, not 0.
Lottery probabilistic/flexible; stride deterministic/stateful.
Unfairness U=completion_first/completion_second; ideal →1.

Heap allocation / C traps

int *a=malloc(n*sizeof(*a)); // sizeof(int) also valid
malloc uninitialized: write before read.
calloc(n,sizeof(*a)) zeroes bytes.
tmp=realloc(a,newsize); if(tmp) a=tmp; // may move
free(a); a=NULL;  free(NULL) safe.
No cast needed for malloc void* in C (needed in C++).
Errors: too small (+1 for '\0'), overflow, leak,
use-after-free, double/invalid free, uninitialized read.
Header before allocation stores size; free gets no size.

Base/bounds + segmentation

Base/bounds: if VA < bounds, PA=base+VA; else trap.
Hardware MMU checks/translates; only kernel sets regs.
OS alloc/free memory, save/restore regs, handle trap.

Segmentation: own base/bounds for code, heap, stack;
VA identifies segment+offset; PA=seg_base+offset.
Stack grows down (negative offset); R/W/X protection;
read-only code can be shared. Virtual gap remains but is
not allocated physically. Variable segments → external
fragmentation. Coarse=few/simple; fine=many/flexible.

Free-space management

Internal fragmentation = waste inside allocated block.
External = total free enough but split into holes.
split: big free → allocation + smaller free
coalesce: merge adjacent free blocks only
compaction moves live blocks; normal C allocator cannot
because existing pointers would become invalid.
Free-list node in free block: current size + next pointer.

first fit first adequate (fast)
next fit continue from saved cursor
best fit smallest adequate (full search/tiny holes)
worst fit largest (full search)
segregated lists: dedicated common-size pools
buddy: split powers of 2; recursively merge free buddy;
easy coalescing, internal fragmentation.
Fit-list problems: choose adequate hole; replace H by
H−request (remove at 0). Next Fit resumes after last chosen;
Worst Fit repeats on current largest hole.

Paging translation (must know)

Virtual memory fixed pages; RAM equal-size frames.
Per-process page table maps VPN→PFN; offset unchanged.
VPN = VA / page_size
offset = VA % page_size
PA = PFN*page_size + offset
PTE_addr = PTBR + VPN*sizeof(PTE)
No external fragmentation; possible internal (last page).
Page tables in RAM: without cache, PTE read + data read.

Example VA=250, page=100, PTBR=1000, PTE=4:
VPN=2, off=50; PTE addr=1000+2*4=1008;
if PFN=7 → PA=7*100+50=750.

PTE bits / page fault flow

PTE: PFN + valid/present + R/W/X + reference + dirty.
valid=0 → illegal virtual page; trap/usually terminate.
valid=1,present=0 → legal but absent RAM; page fault.
Present=0 does not always mean swap: backing may be file,
swap, or recreated zeros. Dirty=1 means RAM copy changed;
backing copy absent/stale → write before eviction.

Fault: trap → process blocks → choose free/victim frame →
if dirty write back → load requested page → set PFN,
present=1 → restart exact faulting instruction.
Page daemon: below low watermark evict until high mark.
Demand load on access; prefetch predicts; clustering groups
disk writes. Thrashing=working sets>RAM → constant paging.

AMAT / locality

AMAT=P_hit*T_memory + P_miss*T_disk; P_hit+P_miss=1.
Tiny miss rate hurts because disk ≫ RAM.
Temporal locality: recent likely reused. Spatial: nearby
likely used. RAM is cache for disk-backed virtual pages.

Replacement policies

OPT/MIN: evict farthest next use; minimum faults; future
unknown → benchmark only.
FIFO: oldest loaded; simple; may show Belady anomaly
(more frames can cause more faults).
Random: low state; unpredictable.
LRU: least recently used; exploits locality; exact tracking
every access too costly. LFU: least frequently used.
Clock approx LRU: circular hand; R=1 → clear/give second
chance/advance; first R=0 → victim. Inspected 1 bits all
become 0. Prefer clean victim (no write) over dirty.
Looping sequential set larger than RAM can defeat LRU.
Thrashing fix: reduce admitted/running processes or add RAM.

RAID comparison (N disks, B capacity, S seq, R random)

LevelUsableFailSeq R/WRand RSmall Rand W
0 stripeN·B0N·SN·RN·R
1 mirrorN·B/21 sure*N·S/2N·RN·R/2
4 fixed parity(N−1)B1(N−1)S(N−1)RR/2
5 rotating parity(N−1)B1(N−1)SN·RN·R/4
*RAID1 may survive one failure per pair; both in same pair
lose data. Stripe=full row; chunk=unit placed per disk.
RAID0 no redundancy. RAID1 two copies. RAID4 one dedicated
parity disk → bottleneck. RAID5 parity rotates.
Parity XOR recovers one missing block. Small parity write:
read old data+parity; write new data+parity = 4 physical I/O.
RAID4: parity disk does 2 each write → R/2. RAID5: four I/O
spread over N disks → N·R/4. Seq MB/s; random IOPS.

Failure / rebuild

Fail-stop: failed disk stops; detected. Redundant RAID runs
degraded, slower; rebuild reconstructs replacement. Hot
spare is installed unused replacement. RAID6: two parity,
capacity (N−2)B, tolerates 2 failures, more write overhead.

Inode / directory / location

inode=index node; per-file metadata: type, size, owner/group,
permissions, times, hard-link count, data-block pointers.
Filename NOT in inode. Directory entry: name → inumber.
Inumber indexes on-disk inode table.

inode byte location = inode_table_start
                      + inumber*sizeof(inode)
inodes/block = block_size/inode_size
inode-table block = inumber*inode_size/block_size
Example start=12KB, inode=256B, inum=32:
12KB+32*256B=20KB (first inode in table block 2).
Superblock (older-model fallback): FS size/layout, block and
inode counts/locations, free-space info, mount state.

Direct / indirect file size

B=block size; A=pointer bytes; P=B/A pointers/block;
D=number direct pointers (course example D=12).
direct capacity = D*B
single = P*B
double = P²*B
triple = P³*B
max = (D+P+P²+P³)*B

B=4KB,A=4B → P=1024:
12 direct=48KB; single=4MB;
direct+single=4144KB; double=4GB; triple=4TB.
Paths: direct inode→data; single crosses 1 pointer block;
double 2; triple 3. Small files use direct; levels allocated
only as file grows. Extent=start block+consecutive length;
compact, but fragmented file needs multiple extents.

Highest-value exam traps

• valid≠present; dirty≠“no disk copy”.
• Base/bounds: add base; paging: divide VA, map VPN→PFN.
• Clock clears every inspected 1 before evicting first 0.
• Page miss loads from disk; RAID reconstruction is failure.
• I/O: RUN→BLOCKED→READY→RUNNING.
• hard link same inode, not copy; symlink stores path.
• malloc memory indeterminate; initialize before reading.
• coalesce adjacent only; C heap cannot compact live ptrs.
• RAID4 divide one parity disk R by 2; RAID5 divide total
  N·R by 4 physical operations.
• inode course example uses 12 direct pointers.
• response uses first run; turnaround uses completion.
• priority boost prevents starvation; cumulative allotment
  prevents MLFQ gaming.
